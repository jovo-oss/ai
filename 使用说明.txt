3. 快速开始（第一次使用）
================================================================================

步骤1：安装依赖包
-----------------
打开PyCharm终端，运行以下命令：

    cd c:\Trae\PyCharm_\ai_chat_system\backend
    pip install -r requirements.txt

等待安装完成，你会看到"Successfully installed"的提示。


步骤2：配置API密钥
------------------
有两种方式配置API密钥：

方式A：通过前端设置面板（推荐）
1. 启动系统后打开浏览器
2. 点击"⚙️ 设置"按钮
3. 在"🔑 API Key 配置"区域输入密钥
4. 点击"保存"按钮
5. API密钥会安全存储在数据库中

方式B：编辑配置文件
编辑 backend\.env 文件，填入你的API密钥：

    DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx

注意：前端设置的API密钥优先级高于.env文件


步骤3：启动系统
----------------
双击运行：启动.bat

系统会自动：
- 启动后端服务（端口8000）
- 启动前端服务器（端口3000）
- 打开浏览器访问
- 显示局域网IP和二维码


步骤4：开始聊天
---------------
1. 在输入框中输入消息
2. 按回车键或点击"发送"按钮
3. 等待AI回复（通常1-3秒）

方法1：一键启动（推荐）
-----------------------

5. 如何配置API密钥
================================================================================

当前系统支持以下AI模型供应商：

- DeepSeek（推荐，成本低）
- OpenAI（GPT系列）
- 阿里云百炼
- 智谱AI
- 百度千帆

方式A：通过前端设置面板（最简单，推荐）
----------------------------------
1. 点击"⚙️ 设置"按钮
2. 找到"🔑 API Key 配置"区域
3. 在对应供应商的输入框中粘贴API Key
4. 点击"保存"按钮
5. API密钥会安全存储在数据库中，下次启动自动加载

方式B：编辑配置文件
------------------
打开文件：backend\.env

配置示例：

    # DeepSeek API密钥（推荐）
    DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx

    # OpenAI API密钥（可选）
    OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx

    # 阿里云百炼 API密钥（可选）
    DASHSCOPE_API_KEY=xxxxxxxxxxxxxxxxxxxxxxxx

    # 智谱AI API密钥（可选）
    ZHIPU_API_KEY=xxxxxxxxxxxxxxxxxxxxxxxx

    # 百度千帆 API密钥（可选）
    BAIDU_API_KEY=xxxxxxxxxxxxxxxxxxxxxxxx

注意：
- 前端设置的API密钥优先级高于.env文件
- API密钥请妥善保管，不要分享给他人
- 如果密钥错误，系统会报错提示
- 可以配置多个供应商，随时切换使用
- 数据库存储的密钥与用户绑定，支持多用户隔离

6. 如何使用聊天界面
================================================================================

基本操作：
---------
1. 在输入框中输入消息
2. 按回车键或点击"发送"按钮
3. 等待AI回复（通常1-3秒）
4. 点击"播放语音"按钮可以听AI朗读回复

界面说明：
---------
- 顶部：聊天标题和模型选择器
- 中间：聊天消息区域
  - 右侧白色气泡：你发送的消息
  - 左侧深色气泡：AI的回复
  - 悬停消息时显示操作按钮（复制、回溯、继续）
- 底部：输入框和发送按钮

消息操作：
---------
-  复制：复制消息内容到剪贴板
- ↩️ 回溯：回到点击的消息位置，删除此消息之后的所有聊天记录
- ▶️ 继续：让AI继续生成更多内容
- 🗑️ 删除：删除单条聊天消息（彻底删除，前后端同步）（新增）
  * 删除操作会同时清理：
    - 前端界面显示
    - 前端本地缓存（localStorage）
    - 后端数据库记录
  * 确保数据完全同步，避免残留数据
- 🔄 重说：重新生成AI回复（仅AI消息）
  * 点击后弹出提示窗口，说明重说功能
  * 可输入自定义提示引导AI按特定方向重说
  * 例如："说得更详细一些"、"换个角度回答"
  * 重说后消息左下角显示"撤回"按钮，可恢复原始消息
- ️ 撤回：撤回重说操作，恢复原始AI回复（仅重说后显示）

重启角色：
---------
- 点击输入框左侧的"重启"按钮
- 确认后将清空当前角色的所有聊天记录和足迹
- 会同时清空本地存储和数据库中的记录（新增）
- 角色恢复到初始状态（显示初始问候语）
- 此操作不可撤销，请谨慎使用

提示：
- 操作按钮悬停时才会显示
- 所有消息都支持操作功能
- 时间显示已优化隐藏，界面更简洁
- 回溯后界面会自动刷新，无需手动操作
- 删除消息仅从本地界面移除，不影响数据库

切换AI模型：
-----------
1. 点击顶部的模型选择器
2. 选择你想使用的模型
3. 系统会自动切换

提示：
- 支持中文和英文对话
- AI会记住之前的聊天内容
- 语音播放需要网络连接

6.1 上下文显示区块（新增）
================================================================================

什么是上下文显示区块？
-------------------
上下文显示区块位于聊天界面左侧，实时显示当前角色的完整上下文信息，
包括角色信息、最近对话、世界书、角色记忆和足迹信息。

显示内容：
---------
上下文显示区块包含以下模块：

1. 👤 角色信息
   - 显示当前角色的名称、描述和性格
   - 显示角色的标签信息
   - 帮助你快速了解当前对话的角色设定

2. 💬 最近对话
   - 显示最近的聊天记录（最多5条）
   - 包含用户和AI的消息
   - 帮助你快速回顾对话历史

3. 📚 世界书参考
   - 显示激活的世界书条目（最多5条）
   - 包含条目名称、内容和标签
   - 帮助你了解AI正在参考哪些背景知识

4. 🧠 角色记忆
   - 显示当前角色的记忆节点（最多5条）
   - 按重要程度排序
   - 帮助你了解角色记住了哪些信息

5. 👣 足迹信息
   - 显示当前角色的足迹信息
   - 包括当前位置、关键物品等
   - 帮助你了解角色的冒险历程

快捷功能：
---------
1. 🔍 搜索功能
   - 在顶部搜索框输入关键词
   - 实时搜索所有上下文内容
   - 快速找到相关信息

2. 📊 统计信息
   - 显示对话数量、世界书条目数、记忆数、足迹数
   - 一目了然了解当前对话的丰富程度

3. 🔄 刷新按钮
   - 手动刷新上下文内容
   - 确保显示最新信息

4. 📖 全部展开 / 📕 全部收起
   - 快速展开或收起所有上下文区块
   - 方便查看或隐藏详细信息

5. 折叠/展开单个区块
   - 点击每个区块的标题可以独立折叠/展开
   - 自定义显示内容

自动刷新机制：
-------------
上下文显示区块会在以下情况自动刷新：
- 发送新消息后
- 执行回溯操作后
- 重启角色后
- 切换角色后

界面特点：
---------
- 深色主题，与整体界面风格一致
- 响应式设计，小屏幕自动隐藏
- 流畅的动画过渡效果
- 直观的图标和标签
- 易于操作的交互设计

使用场景：
---------
- 快速了解当前角色的设定
- 回顾最近的对话内容
- 查看AI正在参考哪些世界书信息
- 了解角色记住了哪些重要信息
- 跟踪角色的冒险历程

提示：
- 上下文显示区块仅显示当前角色的信息
- 不同角色有独立的上下文记录
- 重启角色会清空该角色的所有聊天记录和上下文
- 可以使用搜索功能快速找到相关信息
- 点击区块标题可以折叠/展开详细内容

7. 移动端访问指南
================================================================================

方式一：局域网访问（推荐，速度快）
----------------------------------
适用场景：手机和电脑在同一WiFi网络

步骤：
1. 双击运行 启动.bat
2. 等待启动完成，记下显示的局域网IP
3. 手机浏览器访问：http://[局域网IP]:3000

或者：
1. 在电脑浏览器打开 http://localhost:3000
2. 点击"⚙️ 设置"按钮
3. 在"📱 移动端访问"区域查看局域网IP地址
4. 在手机浏览器中输入该地址访问

注意：
- 手机和电脑需连接同一WiFi网络
- 确保防火墙允许端口3000和8000的访问
- API密钥配置后会自动同步到所有设备

方式二:公网访问(任意网络)
---------------------------
适用场景:手机和电脑不在同一网络

步骤:
1. 双击运行 public_access.bat
2. 等待生成公网地址(类似 https://xxx.loca.lt)
3. 手机访问该公网地址

注意:
- 公网访问速度取决于隧道服务器
- 免费版本每次重启地址会变化
- 保持窗口打开,关闭后服务会停止

8. 角色预设功能
================================================================================

什么是角色预设？
---------------
角色预设是为AI定义不同的身份和性格，让AI以特定角色与你对话。

创建角色：
---------
1. 点击左侧频道栏的"+ 新建频道"
2. 填写角色信息：
   - 角色名称（必填）
   - 角色描述（选填）
   - 角色设定（选填，定义性格和行为）
3. 点击"创建角色"按钮

AI对话分析创建角色（新增）：
--------------------------
1. 打开角色预设面板（点击" 角色预设"按钮）
2. 点击"🔍 对话分析"按钮
3. 选择以下任一方式提供对话内容：
   - 上传聊天记录文件（支持.txt、.json、.csv格式）
   - 粘贴对话内容到文本框
   - 点击"💬 使用当前对话"加载当前聊天记录
4. 选择分析目标（分析AI角色或用户角色）
5. 点击"🔍 开始分析对话"按钮
6. AI会自动分析对话内容，提取角色特征
7. 分析完成后，自动跳转到创建角色表单并填充所有信息
8. 检查并调整信息后，点击"创建角色"保存

使用角色：
---------
1. 在左侧频道列表中点击角色
2. 切换到该角色的聊天频道
3. 开始与角色对话

管理角色：
---------
- 点击频道列表中的角色可切换
- 角色数据自动保存，关闭程序不会丢失
- 可以创建多个不同角色

删除角色（增强功能）（新增）：
------------------------------
- 删除角色时会自动清理所有关联数据，包括：
  * 聊天记录（所有对话消息）
  * 角色记忆（所有记忆节点）
  * 足迹记录（MemoryEvent事件）
  * 上下文日志（ContextLog记录）
  * Author's Note配置（注释设置）
  * 世界书条目（关联的世界书条目）
  * 语音配置（角色的语音参数）
- 使用数据库事务确保数据一致性
- 删除失败时自动回滚，避免数据损坏
- 删除后返回详细的清理统计信息
- 同时清理前端localStorage缓存，避免读取旧数据

提示：
- 角色设定越详细，AI扮演越准确
- 可以为不同场景创建不同角色
- 每个角色有独立的聊天记录
- 对话分析功能可以从真实对话中提取角色特征，更加准确
- 删除角色是不可逆操作，请谨慎执行
- 删除前建议备份重要数据

9. 世界书功能
================================================================================

什么是世界书？
-------------
世界书用于管理背景设定、世界观、人物关系等信息，
帮助AI更好地理解对话背景。

创建世界书条目：
---------------
方式A：手动创建
1. 点击"📚 世界书"按钮
2. 点击"+ 创建条目"
3. 填写信息：
   - 条目ID（英文，必填）
   - 标题（必填）
   - 分类（通用/角色/地点/物品/传说/规则）
   - 内容（必填，详细描述）
   - 标签（选填，用逗号分隔）
4. 点击"创建"按钮

方式B：AI辅助创建
1. 在创建表单中找到"🤖 AI辅助创建"区域
2. 描述你想要的世界背景
3. 点击"✨ 让AI帮我创建"
4. AI会自动生成条目内容并填充表单
5. 你可以修改后再提交

方式C：从角色生成（推荐）
1. 点击"✨ 从角色生成"按钮
2. 选择一个已创建的角色
3. 点击"开始生成"
4. AI会根据角色设定自动生成3-5个相关世界书条目
   - 角色背景故事
   - 世界/地点设定
   - 特殊物品或能力
   - 世界规则或设定
   - 相关背景知识

使用世界书：
-----------
- 激活的条目会在AI对话时自动参考
- 点击"✓ 已激活"按钮激活/停用条目
- 可以创建多个条目管理不同信息

世界书集合管理（新增）：
----------------------

13. 角色语音配置
================================================================================

什么是角色语音配置？
-------------------
角色语音配置允许你为每个角色单独设置个性化的语音参数，
包括音色、语速、音量、音调等，让每个角色都有独特的声音。

打开语音配置面板：
-----------------
1. 点击顶部" 语音配置"按钮
2. 系统会显示所有已创建的角色列表
3. 已配置语音的角色会显示"已配置"徽章
4. 点击任意角色卡片进入配置页面

配置角色语音：
-------------
1. 在角色列表中选择要配置的角色
2. 调整以下语音参数：
   - 启用语音：开启或关闭该角色的语音功能
   - 音色：选择6种不同的音色
     * Alloy - 中性声音
     * Echo - 男声
     * Fable - 英式男声
     * Onyx - 深沉男声
     * Nova - 女声
     * Shimmer - 轻快女声
   - 语速：0.25x - 4.0x（默认1.0x）
   - 音量：0% - 100%（默认100%）
   - 音调：低音 - 高音（默认1.0）
   - 音频格式：MP3、Opus、AAC、FLAC
   - 自动播放：收到回复后自动播放语音
3. 点击"测试语音"按钮试听效果
4. 点击"保存配置"按钮保存设置

管理语音配置：
-------------
- 配置列表显示所有角色及其语音配置状态
- 点击"← 返回列表"可以返回角色列表
- 点击"删除配置"按钮可以删除该角色的语音配置
- 删除配置后，该角色将使用系统默认语音设置

提示：
- 每个角色的语音配置是独立的
- 可以为不同角色设置不同的音色和语速
- 测试语音功能可以帮助你找到最合适的配置
- 语音配置会自动保存，关闭程序不会丢失
- 建议为不同性格的角色选择不同的音色

   * 对话过程中想及时保存重要信息
   * 不希望每次都重新分析全部内容

2. 🔍 全量深度（首次使用推荐）
   - 分析所有聊天记录（最多200条）
   - 完整重建整个知识图谱
   - 确保所有关系链完整
   - 速度较慢但结果最全面
   
   适用场景：
   * 已经聊了很多轮，首次使用提取功能
   * 发现图谱不完整，想要补全缺失的关系
   * 角色剧情有重大进展，需要全面更新

如何使用智能提取：
-----------------
1. 打开足迹面板（选择角色后）
2. 点击顶部的"🧠 智能提取 ▼"按钮
3. 在下拉菜单中选择提取模式：
   - ⚡ 自动增量 — 解析最新20条消息
   - 🔍 全量深度 — 重新分析所有记录
4. 等待AI分析完成（通常5-15秒）
5. 查看提取结果统计：
   - 新建节点数（新发现的实体）
   - 更新节点数（已存在但信息更新的实体）
   - 关系数（建立的新关联）
   - 分析的消息条数
6. 点击"🎯 查看知识图谱"按钮查看生成的图谱
7. 可以点击"🔄 再次提取"进行多次提取

动态提示词策略（智能优化）：
---------------------------
系统会根据聊天记录数量**自动调整**AI的输出要求：

| 聊天记录数 | 提示词版本 | 输出要求 | 适用场景 |
|-----------|----------|---------|---------|
| 1-8条     | 简洁版   | 精简JSON，1-2个关键关系 | 刚开始对话 |
| 9-20条    | 标准版   | 标准格式，2-3个重要关系 | 中等进度 |
| 21+条     | 详细版   | 详细JSON，完整关系链 | 深度对话 |

优势：
- ✅ 避免因内容过长导致JSON被截断
- ✅ 根据数据量合理控制输出复杂度
- ✅ 提高解析成功率，减少失败概率
- ✅ 无需手动配置，全自动适配

聊天记录要求：
-------------
⚠️ **重要提示**：智能提取对聊天记录有一定要求：

最低要求：
- 至少 **4-5条消息**才能进行有效解析
- 消息太少时AI无法提取有意义的实体和关系
- 系统会在不足4条时给出友好提示

推荐数量：
- **5-8条消息**：适合使用"⚡ 自动增量解析"
- **9-20条消息**：两种模式都适用
- **20+条消息**：推荐使用"🔍 全量深度解析"

内容质量建议：
❌ 不好的示例（太简单）：
```
用户: 你好
角色: 你好呀！
用户: 今天天气不错
角色: 是的呢，阳光明媚
```
结果：无法提取任何有效实体和关系

✅ 好的示例（包含具体信息）：
```
用户: 我来到了铁匠铺
角色: 欢迎来到老约翰的铁匠铺！你需要打造什么武器吗？
用户: 我想打造一把剑
角色: 好的，这把剑需要3块铁矿和50金币...
```
结果：成功提取【铁匠铺】、【老约翰】、【剑】等实体及关系

解析失败的原因及解决方法：
-------------------------
原因1：聊天记录数量不足（<3条）
- 系统提示："聊天记录不足（仅 X 条），建议至少进行3轮对话后再提取"
- 解决方法：先进行3-5轮有内容的对话再使用提取功能

原因2：聊天内容太简单
- 如果只是简单的问候或闲聊
- AI无法从中提取结构化信息
- 解决方法：进行一些包含具体信息的对话（地点、人物、物品）

原因3：AI返回空内容
- 网络问题或API服务异常
- 系统提示："AI返回了空内容，请稍后重试"
- 解决方法：稍后重试

原因4：JSON解析失败
- AI返回的内容不是有效的JSON格式
- 系统会自动尝试两级降级：
  1. 标准JSON解析 → 如果失败
  2. 修复JSON + 降低温度重试 → 如果还失败
- 系统提示："AI解析失败，请稍后重试或增加更多对话内容"
- 解决方法：
  * 增加更多聊天记录后再试
  * 使用"全量深度"模式重试

解析结果展示：
------------
成功提取后会显示以下信息：

1. 统计数据：
   - 新建节点数：本次新发现的实体数量
   - 更新节点数：已存在但信息得到更新的实体数
   - 关系数：新建的关联关系数量
   - 分析的消息条数

2. 操作按钮：
   - 🎯 查看知识图谱：跳转到图谱视图查看完整结果
   - 🔄 再次提取：使用相同模式再次提取（可累积完善图谱）

17. 智能上下文管理
================================================================================

什么是智能上下文管理？
-------------------
智能上下文管理系统会自动分析你的聊天内容，
智能匹配并注入相关的世界书、记忆和足迹信息，
避免信息过多导致AI混乱。

工作原理：
---------
1. 关键词提取
   - 系统使用jieba分词库从你的消息中提取关键词
   - 例如："我想去找铁匠打造一把剑" → ['铁匠铺', '打造', '剑']

2. 智能匹配
   - 根据关键词计算世界书、记忆、足迹的相关度
   - 只注入与当前对话相关的内容
   - 例如：提到"铁匠"时，自动匹配铁匠铺世界书和铁匠老王足迹

3. Token预算管理
   - 系统自动估算上下文Token数量
   - 默认上限4000 tokens
   - 超出时自动裁剪最不重要的部分

4. 优先级分配
   - 角色预设：20%（必传）
   - 聊天上下文：40%（最近对话）
   - 记忆/足迹：25%（智能匹配）
   - 世界书：15%（智能匹配）

使用示例：
---------
场景1：你说"我想去找铁匠打造一把剑"
- 系统会注入：
  * 世界书：铁匠铺相关条目
  * 足迹：铁匠老王的信息
  * 记忆：你喜欢剑的偏好（如果有）

场景2：你说"今天天气真好"
- 系统只注入：
  * 角色预设
  * 环境信息（时间、天气）
- 不会注入无关的世界书和记忆

场景3：你说"森林里有什么好玩的？"
- 系统会注入：
  * 世界书：魔法森林相关条目
  * 足迹：森林相关的足迹（如果有）

优势：
-----
✓ 减少Token消耗 - 只注入相关内容，节省成本
✓ 提高AI响应质量 - AI获得更精准的上下文信息
✓ 避免信息杂乱 - 智能过滤不相关的内容
✓ 自动管理 - 无需手动配置，系统自动匹配
✓ 智能衰减 - 长期未使用的记忆降低优先级

配置说明：
---------
当前版本使用默认配置，后续版本会添加配置面板，
允许自定义：
- Token预算上限
- 各模块权重比例
- 匹配阈值
- 最大注入条目数

提示：
- 确保世界书、记忆、足迹的标签填写完整，有助于提高匹配准确度
- 重要度设置合理，可以帮助系统更好地筛选内容
- 系统会自动运行，无需手动干预
- 可以在后端日志中查看上下文注入的详细信息

18. 自动摘要服务（新增）
================================================================================

什么是自动摘要服务？
-------------------
自动摘要服务用于智能压缩长对话记录，当聊天记录过长导致Token溢出时，
系统会自动将早期对话压缩为摘要，保留关键信息，释放Token空间。

工作原理：
---------
1. Token监控
   - 系统实时监控当前对话的Token使用量
   - 当接近模型上下文限制（如4096/8192 tokens）时触发摘要

2. 智能压缩
   - AI自动分析早期对话内容
   - 提取关键信息、重要事件和核心话题
   - 生成简洁的摘要文本

3. 数据替换
   - 将原始消息替换为摘要
   - 保留最近N条完整消息（可配置）
   - 大幅减少Token消耗

4. 摘要质量保证
   - 摘要包含：时间范围、主要话题、关键决策、重要信息
   - 保持角色设定和行为一致性
   - 支持多轮摘要（超长对话）

使用场景：
---------
- 长时间连续聊天（超过50轮）
- 复杂剧情讨论（大量细节）
- 角色养成类对话（需要记住历史）
- 避免Token溢出导致的错误

配置说明：
---------
当前版本使用默认配置：
- 触发阈值：上下文使用率超过80%
- 保留完整消息数：最近20条
- 摘要语言：与对话语言一致
- 摘要详细程度：中等

优势：
-----
✓ 解决Token溢出问题 - 长对话不再报错
✓ 保留关键信息 - 重要内容不会丢失
✓ 自动运行 - 无需手动干预
✓ 智能压缩 - AI理解上下文后生成高质量摘要
✓ 多轮支持 - 超长对话可以多次摘要

提示：
- 摘要是不可逆的，原始消息会被替换
- 建议定期导出重要对话备份
- 摘要质量取决于AI模型能力
- 可以在设置面板调整触发阈值（后续版本）

   - 支持多个条件组合

示例3：引导剧情
- 注释内容："角色即将发现一个秘密，表现出惊讶"
- 效果：AI会在回复中展现惊讶情绪

示例4：保持一致性
- 注释内容："记住角色喜欢猫，提到相关内容"

应用场景：

- 角色扮演：引导AI扮演特定风格
- 创意写作：探索不同的叙事角度
- 教学场景：引导AI按特定方式回答问题

提示：

20. 世界书智能激活系统（新增）
================================================================================

什么是世界书智能激活系统？
---------------------------
世界书智能激活系统是基于关键词匹配和上下文分析的自动化系统，
能够根据你的聊天内容自动激活相关的世界书条目，
无需手动选择，让AI获得最精准的背景知识。

工作原理：
---------
1. 关键词提取
   - 使用jieba分词库分析你的消息
   - 提取实体名词、地点、人物、物品等关键词
   - 例如："我想去铁匠铺找老王" → ['铁匠铺', '老王']

2. 多维度匹配
   - 标题匹配：条目标题包含关键词
   - 内容匹配：条目正文包含关键词
   - 标签匹配：条目标签与关键词相关
   - 综合评分：计算每个条目的相关度分数

3. 上下文感知
   - 分析最近的对话历史
   - 理解当前讨论的话题
   - 提高与当前语境高度相关的条目优先级
   - 降低无关条目的激活概率

4. 智能筛选
   - Token预算管理：限制激活条目总数
   - 相关度阈值：只激活足够相关的条目
   - 去重处理：避免重复或相似条目
   - 动态调整：根据对话进展实时更新

5. 激活反馈
   - 在界面显示哪些条目被激活
   - 显示激活原因（匹配的关键词）
   - 显示相关度评分
   - 允许手动覆盖自动激活结果

配置选项：
---------
1. 匹配灵敏度
   - 高灵敏度：激活更多条目，可能包含边缘相关内容
   - 中等灵敏度：平衡准确性和覆盖率（推荐）
   - 低灵敏度：只激活高度相关的条目

2. 最大激活数量
   - 默认值：5条
   - 可调范围：1-20条
   - 数量越多，Token消耗越大

3. 权重分配
   - 标题权重：30%（标题匹配最重要）
   - 内容权重：40%（内容相关性）
   - 标签权重：20%（标签匹配）
   - 上下文权重：10%（对话历史）

4. 特殊规则
   - 强制激活：某些条目始终激活（如核心设定）
   - 禁止激活：某些条目永不激活（如剧透内容）
   - 互斥规则：某些条目不能同时激活

使用示例：
---------
示例1：地点相关
- 你说："我想去魔法学院学习"
- 系统激活：
  * "魔法学院"条目（标题匹配）
  * "魔法体系"条目（内容匹配）
  * "学院生活"条目（标签匹配）

示例2：人物相关
- 你说："铁匠老王的剑打得真好"
- 系统激活：
  * "铁匠铺"条目（地点关联）
  * "老王"条目（人物匹配）
  * "锻造工艺"条目（技能相关）

示例3：物品相关
- 你说："这把龙鳞剑太厉害了"
- 系统激活：
  * "龙鳞剑"条目（物品匹配）
  * "神兵利器"条目（分类标签）
  * "锻造传说"条目（背景故事）

对比传统方式：
-------------
传统方式（手动激活）：
- 需要自己判断哪些条目相关
- 容易遗漏重要信息
- 可能激活无关条目
- 耗时且容易出错

智能激活系统：
- 全自动匹配，无需手动操作
- 全面扫描所有条目
- 只激活真正相关的内容
- 快速高效，节省时间

优势：
-----
✓ 全自动运行 - 无需手动干预
✓ 精准匹配 - 基于多维度分析
✓ 上下文感知 - 理解对话语义
✓ Token优化 - 只激活必要内容
✓ 实时响应 - 即时更新激活状态
✓ 可配置性 - 支持自定义参数
✓ 透明度 - 显示激活原因和评分

提示：
- 确保世界书条目的标题、内容、标签填写完整
- 使用具体明确的名称（避免模糊词汇）
- 合理设置标签，有助于提高匹配准确度
- 定期检查激活结果，调整配置参数
- 对于特殊场景，可以使用强制激活或禁止激活规则
- 系统会在后台日志中记录每次激活的详细信息

21. 公网访问指南
================================================================================

什么是公网访问?
---------------
公网访问让你可以在任何地方访问聊天系统,
不局限于同一WiFi网络。

使用 localtunnel (推荐)
------------------------------
步骤:
1. 双击运行 public_access.bat
2. 等待生成公网地址(类似 https://xxx-cobras-xxx.loca.lt)
3. 手机或任何设备访问该地址

优点:
- 无需注册账号
- 完全免费
- 一键启动,最简单
- 自动安装,无需配置

注意:
- 免费版本每次重启地址会变化
- 速度取决于隧道服务器
- 需要保持窗口打开
- 关闭窗口后服务会停止
- 首次使用需要安装Node.js

环境要求:
- 需要安装 Node.js (https://nodejs.org/)
- 首次运行会自动安装localtunnel

20. 管理站功能（新增）
================================================================================

什么是管理站？
-------------
管理站是系统的统一控制中心，可以查看和管理所有功能模块，
监控系统运行状态，统计数据信息，方便升级优化和梳理。

访问管理站：
----------
在浏览器中打开：http://localhost:8000/admin

或在聊天系统页面顶部点击"管理站"按钮进入。

管理站包含5大面板：
-----------------

1. 概览面板
   - 8个核心数据卡片：消息总数、角色数量、世界书条目、API配置、记忆节点、足迹事件、闹钟提醒、数据库大小
   - 消息趋势图：近7天的消息数量变化
   - 最近活动流：实时显示消息、记忆、事件、日志等最新动态
   - 每个数据卡片显示总数和激活数/今日数等子统计

2. 模块管理面板
   - 17个功能模块的完整展示
   - 按5大分类排列：
     * 核心（聊天系统、角色预设、世界书、模型广场、API配置）
     * 智能（角色记忆、足迹系统、足迹配置、上下文日志、提示词模板）
     * 语音（角色语音、TTS配置）
     * 交互（闹钟提醒、主动交互、环境感知）
     * 工具（Agent工具、插件系统）
   - 每个模块显示：图标、名称、版本号、描述、数据量、运行状态、分类标签

3. 数据统计面板
   - 角色数据排行：按消息数量排序，显示每个角色的记忆数、事件数、世界书数
   - 消息趋势图：支持7天/14天/30天切换
   - API配置状态：显示所有API配置的名称、规范、地址、密钥状态、激活状态、模型

4. 系统健康面板
   - 系统信息：Python版本、运行平台、CPU核心数
   - 数据库状态：连接状态、数据库大小
   - 环境信息：配置文件是否存在、插件数量、服务端口、调试模式
   - 版本信息：当前版本号、构建日期、27项功能标签一览

5. 数据库面板
   - 数据库表列表：18张表的名称、列数、行数
   - 数据库概览：总大小和各模块数据量
   - 一键优化：点击"优化数据库"按钮执行VACUUM，压缩数据库释放空间

管理站API接口：
-------------
GET  /api/admin/overview          - 系统概览统计
GET  /api/admin/modules           - 模块列表及状态
GET  /api/admin/health            - 系统健康检查
GET  /api/admin/message-chart     - 消息趋势数据（参数：days=7）
GET  /api/admin/character-stats   - 角色数据排行
GET  /api/admin/database/tables   - 数据库表信息
POST /api/admin/database/vacuum   - 数据库优化
GET  /api/admin/recent-activity   - 最近活动记录（参数：limit=20）
GET  /api/admin/api-keys-status   - API配置状态
GET  /api/admin/version-info      - 版本信息

使用场景：
---------
- 查看系统整体运行状况
- 了解各模块的数据量和活跃状态
- 监控消息趋势和用户活跃度
- 检查API配置是否正常
- 优化数据库性能
- 梳理功能模块，规划升级方向
- 快速定位问题模块

提示：
- 管理站数据实时从数据库读取，点击"刷新"按钮可手动更新
- 数据库优化功能会短暂锁定数据库，建议在低峰期使用
- 管理站页面支持响应式布局，手机也可访问
- 管理站与聊天系统共享同一个后端服务，无需额外启动

21. API接口说明
================================================================================

基础地址：http://localhost:8000

1. 发送消息
-----------
POST /api/chat/send

请求体：
{
    "user_id": 1,
    "message": "你好",
    "enable_tts": true,
    "voice": "nova"
}

响应：
{
    "success": true,
    "reply": "你好！有什么可以帮助你的？",
    "audio_base64": "base64编码的音频数据"
}


2. 获取聊天历史
--------------
GET /api/chat/history/{user_id}?limit=50

响应：
{
    "success": true,
    "messages": [
        {
            "role": "user",
            "content": "你好",
            "created_at": "2026-05-19T10:00:00"
        }
    ]
}

22. 常见问题解答
================================================================================

Q1: 启动时报错"ModuleNotFoundError"
A1: 说明依赖没有安装，运行：
    pip install -r requirements.txt

Q2: 发送消息后没有回复
A2: 检查以下几点：
    - API密钥是否正确
    - 网络连接是否正常
    - 查看终端是否有错误信息
    - 确认后端服务正在运行

Q3: 语音播放失败
A3: 可能原因：
    - TTS API密钥未配置
    - 浏览器不支持音频格式
    - 网络连接问题
    - 注意：语音失败不会影响文字回复

Q4: 插件没有生效
A4: 检查：
    - 插件文件是否在 plugins 目录
    - 是否重启了后端服务
    - 插件代码是否有语法错误

Q5: 如何修改服务器端口
A5: 编辑 backend\.env 文件：
    PORT=8080

Q6: 数据库在哪里
A6: 默认在 backend/chat_system.db
    这是一个SQLite数据库文件

Q7: 如何清空聊天记录
A7: 在聊天界面点击"🗑️ 清空"按钮
    或删除 backend/chat_system.db 文件

Q8: 可以使用其他AI模型吗
A8: 可以，在模型广场发现并添加新模型
    或在设置中切换模型

Q9: 手机无法访问
A9: 检查：
    - 手机和电脑是否在同一WiFi
    - 防火墙是否允许端口3000和8000
    - 局域网IP是否正确（运行启动.bat查看）

Q10: 角色/世界书数据丢失
A10: 数据会自动保存，不会丢失

Q11: 智能提取失败，提示"聊天记录不足"
A11: 这是正常现象！智能提取需要足够的上下文信息：
    - 最低要求：3条消息
    - 推荐数量：5-20条消息
    - 解决方法：
      * 先与角色进行几轮有内容的对话
      * 对话中包含具体的地点、人物、物品等信息
      * 等积累足够聊天记录后再使用提取功能
    - 提示：简单的问候（"你好"、"谢谢"）无法提取有效信息

Q12: 智能提取失败，提示"AI解析失败"
A12: AI返回的内容格式有问题，可能原因和解决方法：
    - 原因1：AI返回空内容
      * 解决：检查API密钥是否正确，稍后重试
    - 原因2：JSON格式错误，两级降级都失败
      * 解决：增加更多聊天记录后重试
    - 原因3：网络问题导致响应不完整
      * 解决：检查网络连接后重试
    - 系统会自动尝试两级降级：标准JSON解析 → 修复JSON+重试

Q13: 提取成功但图谱显示不完整
A13: 可能的原因和解决方法：
    - 原因1：聊天内容太简单，没有包含具体实体
      * 解决：进行更丰富的角色扮演对话
    - 原因2：使用的是"自动增量"，只分析了最新20条消息
      * 解决：改用"🔍 全量深度"模式
    - 原因3：关系链未完全建立
      * 解决：多次使用提取功能累积完善
    - 提示：可以手动添加缺失的节点和关系

Q14: 图谱节点太多太乱看不清
A14: 优化建议：
    - 使用搜索功能查找特定节点
    - 按类型筛选显示（只看地点或人物）
    - 删除不重要或重复的节点
    - 删除冗余的关系，只保留核心关系链
    - 使用"全量深度"重建精简后的图谱
    - 定期清理不再需要的旧数据

Q15: 智能提取和旧的AI提取有什么区别
A15: v3.5.1重构后的变化：
    - 旧版有两个入口："经典AI提取"和"智能解析"，功能重复
    - 新版统一为"智能提取"一个入口，操作更简洁
    - 新版只有两种模式：自动增量和全量深度
    - 新版修复了 message_count 未定义导致提取失败的bug
    - 新版优化降级策略为两级，更稳定
    - 建议：使用新的智能提取功能

Q16: 如何提高提取质量
A16: 提高提取效果的技巧：
    - 进行有实质内容的角色扮演对话
    - 在对话中明确提及地点名称、人物名字、物品名称
    - 描述具体的事件和行动（如"我在铁匠铺买了剑"）
    - 避免过于抽象或模糊的表达
    - 积累8-20条高质量聊天记录后再解析
    - 定期使用解析功能保持数据更新
    - 结合手动编辑补充AI遗漏的信息
     如果刷新后看不到，重新打开对应面板即可

Q11: 模型列表为空
A11: 需要先配置API密钥
     在设置面板中配置对应供应商的密钥

Q12: 公网访问地址失效
A12: 免费版本的地址每次重启会变化
     重新运行 public_access.bat 获取新地址

Q13: API配置测试失败
A13: 检查：
     - API密钥是否正确
     - 基础URL是否正确
     - 网络连接是否正常
     - API服务是否可用

Q14: 角色对话失败
A14: 检查：
     - 角色是否创建成功
     - API配置是否正确
     - 后端服务是否正常运行
     - 查看浏览器控制台错误信息

Q15: 前端界面出现错误
A15: 检查：
     - 浏览器控制台（F12）查看具体错误
     - 确认前后端端口一致（默认8000）
     - 刷新页面重试
     - 清除浏览器缓存

Q16: 消息操作按钮不显示
A16: 操作按钮需要悬停在消息上才会显示
     - 鼠标移动到消息气泡上
     - 按钮会自动出现在气泡下方
     - 所有消息（用户和AI）都支持此功能

Q17: 聊天气泡显示异常
A17: 检查：
     - 刷新页面重新加载样式
     - 清除浏览器缓存（Ctrl+Shift+Delete）
     - 确认使用的是最新版本的index.html

Q18: 回溯功能失败
A18: 可能原因：
     - 消息ID格式问题，请重启角色后重试
     - 后端服务未正常运行
     - 网络连接问题
     - 建议：重启角色清空旧消息，新消息使用正确的ID格式

Q19: 重说后如何恢复原始消息
A19: 重说后消息左下角会显示"撤回"按钮
     - 点击"撤回"按钮即可恢复原始AI回复
     - 撤回操作仅对最近一次重说有效

Q20: 重启角色后聊天记录还在吗
A20: 不会，重启角色会清空该角色的所有聊天记录
     - 同时清空本地存储和数据库中的记录
     - 只清空当前角色的记录，不影响其他角色
     - 操作不可撤销，请谨慎使用

Q21: 如何清空所有聊天记录
A21: 有两种方式：
     - 方式1：逐个重启角色，清空每个角色的记录
     - 方式2：运行 backend/clear_all_chat_records_auto.py 脚本
     - 方式3：直接删除 backend/chat_system.db 文件（会清空所有数据）

Q22: 上下文显示区块显示其他角色的对话
A22: 这是旧数据问题，请：
     - 重启该角色清空聊天记录
     - 或运行数据库迁移脚本更新旧数据
     - 新发送的消息会正确关联到当前角色

Q23: ModuleNotFoundError: No module named 'jieba'
A23: 这是缺少依赖的问题，请：
     - 确保在正确的Python环境中运行
     - 进入 backend 目录运行：pip install -r requirements.txt
     - 或单独安装：pip install jieba
     - 使用项目的虚拟环境而不是系统Python

Q24: 删除消息后刷新页面消息又回来了（新增）
A24: 这是旧版本的问题，v3.3.0已修复：
     - 现在删除消息会同时清理前端和后端数据
     - 包括：界面显示、本地缓存、数据库记录
     - 如果问题仍然存在，请：
       * 清除浏览器缓存（Ctrl+Shift+Delete）
       * 重启后端服务
       * 检查浏览器控制台是否有错误

Q25: 删除角色后新对话仍显示已删除角色的回复（新增）
A25: 这是数据隔离问题，v3.3.0已完全修复：
     - 删除角色时自动切换当前角色ID
     - 清理所有关联数据（聊天记录、记忆、足迹等）
     - 清理前端localStorage缓存
     - 使用数据库事务确保一致性
     - 如果仍有问题，请重启系统并清除浏览器缓存

Q26: 删除角色时提示"清理关联数据失败"怎么办（新增）
A26: 可能原因及解决方法：
     - 数据库锁定：关闭其他数据库连接，稍后重试
     - 权限不足：确保有数据库文件读写权限
     - 磁盘空间不足：释放磁盘空间
     - 数据损坏：运行数据库修复工具或恢复备份
     - 联系技术支持并提供错误日志

Q27: 如何查看删除操作是否成功（新增）
A27: 查看删除结果的方法：
     - 删除消息：检查控制台日志[删除消息]信息
     - 删除角色：查看返回的deleted_details统计信息
     - 检查数据库：使用SQLite工具查看对应表是否为空
     - 查看上下文日志：足迹/记忆删除会记录在日志中

Q28: 素黑主题可以切换回原来的颜色吗（新增）
A28: 当前版本使用素黑主题作为默认主题：
     - 配色方案：黑白灰极简设计
     - 如需修改，编辑 frontend/index.html 中的CSS变量
     - 主要变量：--bg-primary, --text-primary, --accent-color等
     - 后续版本可能添加主题切换功能
